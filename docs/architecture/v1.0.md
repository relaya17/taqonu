**Status:** NORMATIVE  
**Date:** 2026-08-11  
**Product codename:** Atlas Core  
**Personal instance:** ArletOS  

This document is the hard contract for v1. It supersedes exploratory feature lists.  
**Do not add capabilities outside the MVP boundary without an ADR that amends this document.**

---

## 1. Product definition

```
ArletOS ≠ AI Agent
ArletOS  = Engineering Intelligence OS + Adaptive QA Intelligence OS
```

| Subsystem | Role |
| --- | --- |
| Evidence | What can be claimed, with provenance |
| Current State | What is true *now* after reconciliation |
| Engineering Graph | How entities relate and impact each other |
| Historical Memory | What was decided / learned over time |
| Portfolio Intelligence | Cross-project patterns and drift |
| QA Intelligence | Adaptive plan→execute→analyze→learn (ADR-009) |
| Agent | Execution brain that *reads* the OS — not the OS itself |
| Security | Least privilege, secrets, audit |
| Connectors | Adapters that feed Evidence/State (not the product center) |

### Non-goals (explicit)

- Not an IDE / code editor competitor (Cursor, Claude Code, Codex remain editors)
- Not autonomous production writes in v1
- Not a kitchen-sink integration suite in MVP

```
Cursor / Claude Code / Codex
          ↓
       ArletOS  (truth, state, memory, graph)
          ↓
Portfolio Engineering Intelligence
```

### Core question loop

```
              ARLETOS
                 │
       "What is true?"
                 │
        ┌────────┴────────┐
        ↓                 ↓
   Evidence           Current State
        │                 │
        └────────┬────────┘
                 ↓
        Engineering Graph
                 ↓
        Historical Memory
                 ↓
       Portfolio Intelligence
                 ↓
             AI Agent
                 ↓
        What should happen?
```

## 2. Investment pillars (v1.1)

Work priority is fixed:

1. **State Reconciliation** — fuse connector observations into Current State  
2. **Temporal Memory + Decisions** — typed, dated, supersedable  
3. **Evidence / Provenance** — every claim points to source+time+confidence  
4. **Engineering Graph** — impact, duplication, decision→code lineage  
5. **Portfolio Intelligence** — patterns across BrokerOS, HotelOS, CaseFlow, …  
6. **QA Intelligence** — adaptive risk-based verification + regression LEARN (see `qa-intelligence.md`, ADR-009)

Connectors (GitHub first; Vercel/Render/Netlify later; Google last) are **feeds**, not pillars.

## 4. Epistemic model (normative)

Every claim-bearing object MUST carry:

| Field | Required |
| --- | --- |
| `epistemicState` | FACT \| CONFIRMED \| INFERRED \| PROPOSED \| UNKNOWN \| CONFLICTED |
| `confidence` | 0..1 |
| `evidenceIds` | ≥0 references |
| `observedAt` / `asOf` | timestamp |
| `source` + `sourceType` | provenance |
| `version` | optional but preferred for repo/docs |

| State | Meaning | May be shown as “true now”? |
| --- | --- | --- |
| FACT | Directly observed from a connector/system | Yes, if not superseded |
| CONFIRMED | Supported by authoritative evidence | Yes |
| INFERRED | Derived by Atlas | Only with label |
| PROPOSED | Agent recommendation | Never as fact |
| UNKNOWN | Insufficient evidence | No |
| CONFLICTED | Credible sources disagree | No — show both |

**Silent merge of opposing claims is forbidden.** Conflicts remain CONFLICTED until an explicit resolution record exists.

Knowledge categories (never silently fused):

1. `REPOSITORY_EVIDENCE` — what exists in git  
2. `DECISION_MEMORY` — what was decided  
3. `EVENT_MEMORY` — what happened  
4. `ROADMAP_TASK` — what should happen next  
5. `VERIFIED_WEB_KNOWLEDGE` — post-MVP  
6. `GENERATED_REASONING` — what the AI thinks

## 5. Current State (system center)

Every project has a living **Project State** document composed of slices:

```
PROJECT STATE
├── Code
├── Git
├── Architecture
├── Dependencies
├── Database
├── Environment          (metadata only — never secret values)
├── Deployment           (post-MVP connectors feed this)
├── Tests
├── Security
├── Decisions
├── Tasks
└── Risks
```

### State reconciliation

```
GitHub (+ later deploy connectors)
   + Memory
   + Decisions
        ↓
STATE RECONCILIATION JOB
        ↓
project_state_snapshots (as_of, slices[], conflicts[])
        ↓
WHAT IS TRUE NOW?
```

Rules:

- Each slice has its own epistemic state and evidence set  
- Reconciliation NEVER invents FACT from PROPOSED  
- Stale slices expire via `validUntil` / freshness policy  
- `GET /api/v1/projects/:id/state` is the primary product read API

## 8. Agent lifecycle (gated)

```
READ → ANALYZE → PLAN → APPROVE → WRITE → VERIFY
```

| Mode | Allowed in MVP | Notes |
| --- | --- | --- |
| READ | Yes | Repos, state, memory, graph |
| ANALYZE | Yes | Inference, labeled INFERRED |
| PLAN | Yes | PROPOSED actions only |
| APPROVE | Human | Required before WRITE |
| WRITE | **Blocked until eval gates pass** | Branch/commit/PR later |
| VERIFY | Required after any write | Reconcile state |

**No path:** `USER → AI → PRODUCTION`.

### Evaluation before autonomy

Harness dimensions (must be measured continuously):

- Accuracy · Retrieval · Memory · Evidence · Security · Authorization · Tool selection · Regression  

WRITE tools remain `requiresApproval: true` even after gates open.

## 9. Permissions model

### Identity

- Browser → Supabase Auth session → RLS on all exposed tables  
- Sensitive/service operations → API with service role (server only)  

### Connector credentials

```
OAuth / GitHub App
  → encrypted credential store
  → short-lived access token
  → tool execution
  → discard / rotate
```

No master API key shared across connectors.  
Env secret **values** are DENY for all tools; metadata MAY be READ.

### GitHub App (MVP)

Read: metadata, contents, statuses, issues, pull_requests, actions, deployments.  
Deny initially: contents:write, workflows:write, administration:write, secrets:write.

### RLS ownership

All tenant rows keyed by `owner_id` (or via project ownership).  
Portfolio queries are scoped to the authenticated owner’s projects only.

## 10. Event model

### Envelope

```json
{
  "id": "uuid",
  "type": "github.push.received",
  "occurredAt": "ISO-8601",
  "ownerId": "uuid",
  "projectId": "uuid|null",
  "correlationId": "uuid",
  "causationId": "uuid|null",
  "epistemicState": "FACT",
  "payload": {}
}
```

### Core event types (v1)

| Type | Producer | Consumers |
| --- | --- | --- |
| `github.webhook.received` | API | Persist, queue |
| `github.sync.completed` | Worker | State reconcile, graph upsert |
| `evidence.recorded` | Worker/API | Claim index |
| `memory.created` / `memory.superseded` | API/Agent | State, graph |
| `decision.created` / `decision.superseded` | API | State, graph |
| `state.reconciled` | Worker | Snapshot publish |
| `graph.upserted` | Worker | Impact index |
| `agent.run.started` / `completed` | API | Audit |
| `authorization.denied` | Policy | Security events |
| `secret.detected` | Detector | Block + security_events |

Events are append-only. Side effects go through workers, not chat.

## 13. Definition of done (Architecture / MVP)

MVP is **not** “chat works”.

- [ ] Portfolio of projects registered  
- [ ] GitHub connected + synced for ≥1 repo  
- [ ] Current State endpoint returns sliced, labeled truth  
- [ ] State reconciliation job runs on sync  
- [ ] Memory + decisions with temporal validity + supersession  
- [ ] Evidence attached to claims; conflicts retained  
- [ ] Graph supports impact query  
- [ ] Portfolio patterns API returns cross-project signals  
- [ ] Agent restricted to READ/ANALYZE/PLAN  
- [ ] Eval harness exists and blocks WRITE  
- [ ] RLS on; webhooks signed; secrets redacted  
- [ ] Shared Zod contracts; no `any`; CI green

## 14. Amendment process

Changes to MVP boundary, epistemic rules, or WRITE unlock require:

1. New ADR under `docs/adr/`  
2. Schema + migration PR  
3. Update to this file’s version (`v1.1`, …)  

Connectors may be added without expanding product center as long as they only emit Evidence/Events for reconciliation.
