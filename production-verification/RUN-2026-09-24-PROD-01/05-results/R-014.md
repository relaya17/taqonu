## Expected behavior

A controlled, intentionally induced failure is represented in production as a failure — not
silently swallowed and not reported as success. The failure is surfaced to the caller,
recorded, and visible in the error/observation surfaces.

## Actual behavior

The scenario could not be executed:

- Inducing a controlled application-level failure requires reaching application code through
  the API. Every route on `https://taqonu-api.vercel.app` returns 503 before routing, so the
  controlled failure fixture is never reached.
- Failure read-back: `GET /api/v1/error-aggregates` and `GET /api/v1/executions` both return
  401 `Control Plane authentication required`.

**Explicit non-substitution.** The production API is itself currently failing with a 503. That
is an *infrastructure boot failure* in the deployed serverless bundle, occurring before any
Atlas application code runs. It is not the controlled, application-level failure this item
requires, and it demonstrates nothing about how Atlas represents a handled failure. It is
recorded once at R-001 and is **not** substituted for this scenario or used to claim a pass.
