## Expected behavior

One complete real production workflow executes end to end:

```
User / Request → Agent Identity → Policy → Risk → Supervision →
Approval where required → Dispatch Guard → Action → Event → Audit →
Evidence Reference
```

Every stage is observable, and the chain is traceable from the originating request to the
final evidence reference.

## Actual behavior

The chain was not executed. It could not begin: the first stage after the request
(Agent Identity) is reached through the API, and every route on
`https://taqonu-api.vercel.app` returns 503 before routing. None of the downstream stages
(Policy, Risk, Supervision, Approval, Dispatch Guard, Action, Event, Audit, Evidence) was
entered.

Per plan §4, GATE 4 runs only after GATES 0–3. GATE 0 resulted in FAILED (R-001) and GATES
1–3 are entirely BLOCKED (R-002 … R-015), so no prerequisite stage of the golden chain has
production evidence behind it. Executing GATE 4 regardless would not produce verification —
only a second observation of the same 503.

What *was* observed in production, and what it does not establish:

- `taqonu-web.vercel.app` serves its shell, performs locale routing, and executes all four
  legacy redirects correctly (307 with the correct `Location`, 200 at each destination). This
  is genuine production evidence for the web redirect layer, recorded at
  `01-execution/web-legacy-redirects-production.txt`. It is supplementary — it is not an
  R-item and is not counted toward any R-item.
- `taqonu-control-plane.vercel.app` answers `GET /api/v1/status` with 200 and refuses all
  eleven other probed endpoints with 401. This is consistent with the ADR-021 fail-closed
  design, but it is evidence that access control is engaged, not that any governed workflow
  executes correctly.
- `taqonu-admin.vercel.app` returns its shell with 200.

None of the above traverses the golden chain. No stage of it is claimed as verified.
