## Expected behavior

One user Atlas memory/context never leaks into another user session: user A context stays in
A responses, user B context stays in B responses, and neither appears in the other.

## Actual behavior

The scenario could not be executed:

- The memory/context path runs through the API. Every route on
  `https://taqonu-api.vercel.app` returns 503 before routing, so no session could be
  established for user A or user B and no memory could be written or read.
- The web surface (`https://taqonu-web.vercel.app`) serves its shell and locale routing, but
  any authenticated workbench session it renders depends on the same API.

No production user accounts were created, no production session was opened, and no real user
data was read. Per the plan direction for this item, **no real customer content was exposed
in any evidence file** — none was obtained in the first place.
