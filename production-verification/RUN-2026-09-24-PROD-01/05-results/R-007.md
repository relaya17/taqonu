## Expected behavior

With a kill-switch engaged for a category, a subsequent action in that category is refused,
and the refusal is observable and audited. Activation state, activating identity, attempted
action, block result and audit record are all recorded.

## Actual behavior

The scenario could not be executed:

- Kill-switch state: `GET /api/v1/kill-switches` returns 401 `Control Plane authentication
  required`, so the current production kill-switch state is unknown.
- Kill-switch activation: `POST /api/v1/kill-switches/:category` was **deliberately not
  attempted**. Engaging a production kill-switch is a live safety control affecting real
  traffic; doing so without an owner mandate is outside the scope of a verification run
  (plan §1.2, §10).
- The action that would have been refused originates through the API, which returns 503 on
  every route.

No kill-switch was engaged or disengaged. No security control was bypassed or weakened.
