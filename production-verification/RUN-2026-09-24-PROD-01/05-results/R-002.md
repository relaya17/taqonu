## Expected behavior

One controlled production agent action is attributable to the correct agent identity, with
initiating agent, agent identity, action, timestamp, target, resulting event and associated
audit record all observable.

## Actual behavior

The scenario could not be executed. Both production paths that could carry it are
unavailable to this operator:

- Agent action dispatch path: `https://taqonu-api.vercel.app/*` returns 503 on every route,
  before routing (see R-001 Finding 1).
- Identity inventory on the Control Plane: `GET /api/v1/agents` and `GET /api/v1/agents/stats`
  both return 401 `Control Plane authentication required`.

No action was dispatched, no approval was requested, no state was mutated. No agent identity
was observed in production.

## Reason

external blocker:
  (a) Production API unavailable — every route returns 503 CONFIG_ERROR from a boot failure
      in the deployed serverless bundle. Origin is an Atlas deployment-artifact defect, not
      a provider outage; it is recorded once as FAILED at R-001 rather than re-counted as a
      separate defect on each dependent item.
  (b) Production Control Plane governance endpoints require `ATLAS_CONTROL_PLANE_TOKEN`,
      which this operator does not hold.

required condition:
  (a) A production API deployment that boots — the linux-x64 `node-pty` native binding must
      resolve, or `node-pty` must be externalised from the Vercel bundle.
  (b) A production Control Plane operator or owner token, provisioned through the normal
      secret-distribution path.
  (c) A deployment-to-commit binding, so any result can be attributed to a known build.
